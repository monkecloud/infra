# Platform

Exported from the running cluster and verified byte-identical to it before committing, so
Flux adopting these caused no restart of anything.

## Deliberately absent

**Traefik itself.** k3s ships `traefik` and `traefik-crd` as bundled HelmCharts served from
`%{KUBERNETES_API}%/static/charts/`. k3s owns and recreates them, so committing them here
would mean two systems fighting over the same objects. We manage only the `HelmChartConfig`
in `../platform-config/`, which is the supported way to customise a k3s-bundled chart — a
`kubectl patch` gets reverted the next time the packaged chart reconciles.

**Operator PKI and `chart-values-*` secrets.** Generated by the operators and by k3s's
helm-controller. They regenerate themselves; committing them would pin stale values.

## Notes

`operators.yaml` uses k3s `HelmChart` CRs rather than Flux `HelmRelease`, matching what is
already deployed. That is why `helm-controller` is not installed — k3s has its own, so
installing Flux's would add a second Helm engine for no gain.

`kube-router` runs firewall-only (`--run-router=false --run-firewall=true
--run-service-proxy=false --enable-cni=false`). It is the NetworkPolicy engine; tenant
egress isolation stops working without it.
